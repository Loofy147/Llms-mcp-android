Targets A-02/A-03/A-04.

```text
SCHEMA PROPOSED
```

1. execution admission versus `RUNNING` semantics;
2. exact ExecutionClaim lifecycle;
3. effect-group aggregate-state invariant strategy;
4. zero-effect Action semantics;
5. stale-write/versioning mechanism;
6. event/provenance requirement;
7. deterministic legacy-journal migration semantics.

After those are resolved:

```text
1. Add the authoritative transactional backend.
2. Add state-transition result types.
3. Add execution-claim identity/lifecycle.
4. Add atomic group-reservation transaction.
5. Make terminal writes transition-checked.
6. Add deterministic fault-injection tests.
7. Test multiple database connections/instances.
8. Test reopen/recovery after each fault point.
9. Re-run the complete transaction matrix.
```

SQLite/Room is the preferred backend direction based on its transaction and concurrency primitives, but this remains an implementation decision until the schema/invariant review is closed.
