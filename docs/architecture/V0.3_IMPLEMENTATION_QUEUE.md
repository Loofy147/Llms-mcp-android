# v0.3 Implementation Queue

Status: Active
Date: 2026-09-06

## Now

### Q1 — Unified durable control-plane transaction

Targets A-02/A-03/A-04.

Unify or transactionally coordinate:

```text
Approval
Run state
Effect reservation
```

Required properties:

- single-winner approval resolution;
- crash-recoverable transition to execution;
- atomic logical reservation of all effects in an Action plan;
- process-safe journal coordination;
- terminal Run state cannot be overwritten.

Evidence: E-13, E-14.

### Q2 — Immutable semantic provenance

Target A-05.

Persist immutable identities for:

```text
Action definition
Capability definition
Verifier definition
```

A version number is metadata; it is not a cryptographic or immutable definition identity.

Evidence: E-15.

### Q3 — Concrete authorization

Targets A-06/A-07/A-08/A-09.

Introduce an explicit principal/authentication boundary, invocation-level policy input, and structured scope semantics before broadening external or device capabilities.

Evidence: E-16.

### Q4 — Independent verification

Targets A-10/A-11.

Remove terminal-success dependence on executor/action self-attestation and introduce a verifier contract with durable verifier provenance.

Evidence: E-17.

### Q5 — Resource and cancellation controls

Targets A-13/A-14.

Bound model/tool loops and propagate cancellation to HTTP/tool execution.

Evidence: E-18.

## After semantic closure

Only then begin the read-only developer capability proving ground:

```text
dev.workspace.inspect
dev.file.read
dev.file.hash
dev.git.status
dev.git.diff
```

Run the 20-case benchmark across at least three repository states.

The first write capability should be `dev.file.patch`, gated by before-state capture, narrow path scope, expected diff, post-apply observation, and independent verification.
