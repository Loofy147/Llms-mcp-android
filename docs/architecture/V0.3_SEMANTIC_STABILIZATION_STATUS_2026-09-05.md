## Completed in this increment

### A-01 — direct planning failure boundary

**Resolved in code.** The direct `ALLOW` activation path no longer evaluates `Action.plan` outside the runtime failure boundary.

New behavior:

```text
Activation
  -> policy ALLOW
  -> Action.plan
       success -> execute
       failure -> persisted RunStatus.FAILED
```

The failure is represented as a terminal Run with the planner exception message retained as `denialReason`; no capability invocation is materialized and no Action reduction occurs.

Regression test:

```text
directPlanningFailureBecomesPersistedFailedRun
```
