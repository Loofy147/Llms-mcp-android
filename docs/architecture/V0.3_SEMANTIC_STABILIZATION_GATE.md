# v0.3 Semantic Stabilization Gate

Status: Active gate
Date: 2026-09-06

The project is not permitted to expand capability breadth until the following semantic boundaries are either implemented and tested or explicitly accepted as provisional with evidence limitations documented.

## Gate order

### G0 — planning boundary

Status: CLOSED by E-12.

Direct `Action.plan` failures are normalized into persisted `FAILED` Runs.

### G1 — approval/execution durability

Status: OPEN.

Implement one durable control-plane transaction or an equivalent recoverable compare-and-swap protocol covering Run state, approval resolution, and effect reservation.

Required evidence: E-13.

### G2 — concurrency

Status: OPEN.

Cross-instance/process journal operations require atomicity for approval consumption, Run transitions, and effect reservation.

Required evidence: E-14.

### G3 — immutable semantics

Status: OPEN.

Persist Action and verifier definition identity beyond `(id, version)`; historical Runs must reconstruct the exact semantic definition used for authorization and execution.

Required evidence: E-15.

### G4 — concrete authorization

Status: OPEN.

Authorization must evaluate the concrete CapabilityInvocation, not only the parent Action declaration. Activation source and principal identity must have explicit semantic roles.

Required evidence: E-16.

### G5 — independent verification

Status: OPEN.

Terminal success must be derived from observations and an independent verifier contract, not from a capability-owned or action-owned success flag alone.

Required evidence: E-17.

### G6 — resource lifecycle

Status: OPEN.

Model/tool loops require explicit iteration, call-count, time, input/history, and output budgets; cancellation must reach the underlying transport and tool execution.

Required evidence: E-18.

## Expansion rule

No new consequential capability family should be treated as production-ready while G1–G5 remain open.

Read-only developer capabilities may be developed as a proving-ground branch only when each capability explicitly records which gates it depends on and does not broaden the control-plane authority.

## Evidence language

Use:

```text
IMPLEMENTED
PROVISIONALLY VERIFIED
OPEN
CONFLICT
```

Do not use `secure`, `atomic`, `exactly-once`, `production-ready`, or equivalent broad claims unless the corresponding evidence level supports them.
